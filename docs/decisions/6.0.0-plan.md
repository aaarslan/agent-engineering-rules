## State machine and mutation contract (sections 8–9)

Absent → pending install → stable; stable → pending install/update/move → stable;
stable → pending uninstall → absent. Pending records include operation ID/kind,
original/desired complete selections and inventories, normalized before/after
ownership, raw before/after bytes hashes, retention mode and exact planned paths.
Stable state commits last. Omitted later selections retain validated state.

A real operation acquires an exclusive owner-identified run lock, validates state
and package-supplied deletion authority, preflights the complete plan, durably
records pending state, rechecks exact snapshots for every mutation, checks final
inventory, retires recognized paths/prunes only empty directories and commits.
Instruction moves preserve current consumer text outside both blocks, including
BOM/EOL/final-newline behavior. A resumed outside-text projection is journaled
before mutation. Keep-modified uninstall reports and detaches retained material.

Dry-run/check create nothing. Check inspects lock and repeats state identity to
report activity/unstable snapshots. Lock release requires its unchanged owner
bytes and filesystem identity. Stale/partial locks require manual inspection and
confirmation the mutator stopped; no automatic stale-lock removal occurs.

Same-operation complete temporaries are hash checked and removed under the lock.
Partial/modified temporaries and journal remnants before the first journal rename
require backup/inspection and explicit manual removal; absence of a ledger does
not adopt them. Real child SIGKILL after payload and stable-state temporary sync
was recovered after observed termination and manual stale-lock removal. Two real
mutator processes were tested. Durability covers process interruption with file
sync/rename, not power loss or a hostile process controlling the same filesystem.

## Decisions and material deviations

- Adopted the reviewed explicit `representation:PATH` destinations and canonical
  roots. Contributor instructions were updated at cutover; source-only/two-host
  build instructions govern the archived v5 fixture. Shared reference copies use
  a fixed, nonrecursive renderer so independently distributed skills retain one
  wording authority. No required skill or external-resource dependency remains.
- Raised the raw kernel byte guard from 5,120 to 6,400 to accommodate the approved
  authority/inspection/evidence/reporting qualifications (§6.3, §10.2), while
  retaining the 8,000-byte composed guard and physical-line accounting. This is
  an AER regression guard, not a measured optimum. Descriptions use format maxima;
  no lexical-overlap, grammatical-person or exact completion-sentence rule exists.
- Retained the complete original v5 fixture/test suite rather than deleting
  assertions whose modules retired. V5 host-build, init/update/doctor, old context
  layouts and hook dispatch are intentionally inactive in v6; replacements and
  ownership invariants are tested against the active CLI and packed artifact.
- Fixtures were developed alongside mechanical content porting; no model-driven
  optimization or live evaluation preceded the frozen requirements/rubric.
  Separate paired protocols await actual configuration/review/authorization;
  filling the narrow schema with invented facts would be invalid (§11).
- Historical inventory authority comes from the package, never arbitrary ledger
  paths/hashes. Upgrade/downgrade fixtures exercise recognized prior identities;
  unknown versions refuse and require their pinned package. The initial 6.0.0
  release has no earlier v6 inventory to ship (§9.2).
- Optional portable and Claude plugin channels are deferred (§3, §8.3): no final
  discovery/invocation/update-owner evidence. Required direct integrations ship
  their complete metadata/adapter inventory; their session probes remain gates.

Final bounded review corrected absent/pending `check` races, stale package-lock
metadata and packed document/resource links. The stronger packed-link assertion
failed on both runtimes before the reviewer adapter correction; that duplicated
v5 procedure was removed in favor of the installed canonical review skill.
Rendered inventories now validate resource closure, and final full gates passed.
Standalone diagnostic defaults are now generated from canonical thresholds;
composed physical-line guards include block metadata, with a negative regression.
The dated public capability matrix ships explicitly; research/decision records
remain repository-only and are linked as such.
