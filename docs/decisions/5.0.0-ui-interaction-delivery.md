# V5 UI interaction delivery

## Observed failure

The user-requested local comparison `todo-comparison-20260912-01` used fresh GPT-6 Astra subagents at low effort, the same disclosed todo task and one attempt per arm. The reviewer scored the baseline eight of ten groups and v5 nine of ten. Both apps rebuilt their lists after checkbox activation and lost keyboard focus; v5 also lost focus after cancelling an edit. V5 avoided the baseline's stale-draft retry failure. Scores reflect that local rubric and its interpretation, not a general efficacy result.

The original v5 treatment already required deliberate focus handling in its optional web reference. Its root made consultation depend on recognized uncertainty, and the final checks established activation without establishing continued keyboard use. Whether the agent read the reference is not established; absent delivery and nonadherence cannot be separated from this pair alone.

## Decision

Keep the universal kernel unchanged. Put the compact `UI-01` obligation in a shared source fragment included directly in selected web-UI content for both hosts and in the detailed web reference. The obligation asks for evidence after the state transition, including visible focus and the next keyboard action. The reference explains implicated toggle, save, Cancel/Escape, removal and filtering cases; no test framework or mandatory diagnostic is introduced.

This deliberately replaces the previous pointer-only context rule where an observed failure justifies a compact direct obligation. Full references remain optional. Source composition preserves one wording authority, and shortened index prose offsets the added content within the existing load ceilings.

The Codex installer selects context content by physical row. The shared clause must stay on the same row as its owning reference, without another context's pointer. Validate that structure and the single-paragraph fragment, refuse malformed composition, and protect selection, removal, restoration and consumer ownership through installation checks. Claude route budgets apply to expanded source content; runtime accounting also includes generated path metadata and review-fork content.

## Evidence boundary

The original apps, prompts, treatment, scoring and report are preserved outside the repository. The archived report SHA-256 is `1cb63284bf8a6d34755e569b21ecc96df80a13361d5cd8bc2a92d2101126235d`; treatment `AGENTS.md` SHA-256 is `53c1c75ab455a1aa6301912ec74dee80bcb6c2a64073b662b603f89c8fad59df`. Neither is replaced by the revised distribution.

No efficacy claim is made for this revision. Source and installation checks can establish delivery and selection, not that a model follows the clause or produces a perfect app. A future efficacy comparison needs a separately frozen treatment and independently specified tasks; repeating the known todo case would be a regression probe, not independent proof of improvement.
